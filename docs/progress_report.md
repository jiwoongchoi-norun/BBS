# BBS 프로젝트 진행 보고서

## 1. 프로젝트 개요

본 프로젝트는 Node.js, Express, EJS, OracleDB를 기반으로 하는 게시판 과제 프로젝트이다.
교수님 수업자료와 과제 요구사항을 기준으로 게시판의 기본 흐름을 복구하고, 제출 전 미완료 기능을 단계적으로 보완하는 방향으로 진행 중이다.

## 2. 현재 구현 결과

현재까지 확인된 구현 범위는 다음과 같다.

- 게시글 목록
- 글쓰기
- 글읽기
- 글수정
- 글삭제
- 검색
- 로그인
- 로그아웃
- 회원가입
- 회원정보 수정
- 세션 처리
- Bootstrap 기반 기본 UI
- `.env` 기반 환경설정 분리
- `SESSION_SECRET` 환경변수 사용
- 게시글 soft delete 처리

위 기능을 기준으로 기본적인 게시판 사용 흐름은 시연 가능한 상태이다.

## 3. 주요 개선 사항

### 3.1 환경설정 분리

- DB 접속 정보는 `.env` 기반으로 분리되어 있다.
- `SESSION_SECRET`은 코드에 직접 작성하지 않고 환경변수로 관리한다.
- 필수 환경변수가 없으면 애플리케이션 실행을 중단하도록 처리되어 있다.

### 3.2 세션 처리 정리

- 로그인 성공 시 `req.session.user`에 사용자 정보를 저장한다.
- 세션에는 사용자 식별에 필요한 최소 정보만 저장한다.
- 비밀번호는 세션에 저장하지 않는다.

### 3.3 로그인 필요 기능 보호

`routes/bbs.js`에 `requireLogin()` 형태의 공통 확인 로직이 추가되어 있다.
현재 다음 기능에 적용되어 있다.

- 글쓰기 화면
- 글 저장
- 글수정 화면
- 글수정 저장
- 글삭제
- 회원정보 수정 저장

### 3.4 게시글 soft delete 적용

- 게시글 삭제 시 실제 `DELETE`를 실행하지 않는다.
- `BBS.OK = 0`으로 상태만 변경한다.
- 목록, 상세, 수정 조회에서는 `OK = 1`인 게시글만 대상으로 한다.

### 3.5 검색 조건 정리

- 제목 검색
- 내용 검색
- 작성자 검색
- 제목 + 내용 검색

제목 + 내용 검색은 `OR` 조건을 괄호로 묶어 `OK = 1` 조건과 함께 올바르게 적용되도록 정리되어 있다.

## 6. DB 구성

현재 스키마 기준 주요 객체는 다음과 같다.

- `LOGIN`
- `BBS`
- `BBS_SEQ`

현재 데이터 구조는 기본 인증과 게시글 기능을 충족하는 수준이다.
댓글, 파일 업로드, 조회수, 페이징 기능을 위해서는 추가 테이블 또는 컬럼 설계가 필요하다.

## 7. 현재 남은 과제

제출 전 우선 보완이 필요한 항목은 다음과 같다.

1. bcrypt를 이용한 비밀번호 암호화 적용
2. SQL bind variable 적용
3. 조회수 구현
4. 페이징 구현
5. 댓글 구현
6. 파일 업로드 구현

위 항목 중 비밀번호 암호화, 조회수, 페이징, 댓글, 파일 업로드는 과제 완성도와 직접 연결되는 필수 보완 대상이다.

## 8. 기술적 한계 및 리스크

- 비밀번호가 아직 평문 저장 방식이다.
- SQL 문자열 직접 결합이 남아 있어 SQL Injection 위험이 있다.
- 게시글 수정 / 삭제에 작성자 권한 체크가 없다.
- 삭제 요청이 `GET /bbs/delete` 방식으로 처리된다.
- 자동 테스트 코드가 준비되어 있지 않다.

현재 구조는 과제 시연에는 사용할 수 있지만, 보안성과 유지보수성 측면에서는 추가 개선이 필요하다.

## 9. 종합 평가

현재 프로젝트는 게시판 과제의 기본 기능 흐름이 상당 부분 복구된 상태이다.
세션 처리, 로그인 필요 기능 보호, soft delete, 환경변수 분리까지 반영되어 기존보다 안정적으로 동작할 수 있는 기반이 마련되어 있다.

다만 과제 요구사항을 완전히 충족하려면 비밀번호 암호화와 남은 필수 기능 구현이 추가로 필요하다.
다음 단계에서는 보안 개선보다 먼저 제출 완성도에 직접 영향을 주는 필수 기능을 우선 구현하는 것이 적절하다.
